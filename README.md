# Secure X VPN subscription relay

FastAPI service with a subscription relay and an independent admin panel. Secure X combines the primary provider subscription with the SAS subscription source. `/health` remains a lightweight health check. Relay request headers and cache are separate from panel synchronization.

The admin panel manages subscriber profiles and servers in Supabase. Changes made in the panel are pushed immediately to Google Drive through a protected Apps Script Web App. The existing five-minute Apps Script trigger remains as a recovery path. The already-connected legacy Drive file is kept as **Основная (legacy)** so its existing URL remains unchanged. Its real file ID is stored by the application and is intentionally omitted from this documentation. Example only: `YOUR_EXISTING_DRIVE_FILE_ID`.

## Render environment

Create or update the Render Web Service from `render.yaml`. Set these environment values in the service dashboard; secret values are never stored in this repository:

| Variable | Required | Purpose |
| --- | --- | --- |
| `SUBSCRIPTION_URL` | Yes for relay and admin sync | Provider subscription URL |
| `SAS_SUBSCRIPTION_URL` | Yes for SAS server merge | SAS subscription source URL; a default is set in `render.yaml` |
| `UPSTREAM_USER_AGENT` | No | Provider request User-Agent; panel uses `Happ` when empty |
| `UPSTREAM_X_HWID` | No | Fixed authorized device identity |
| `UPSTREAM_X_DEVICE_INFO` | No | Optional upstream device metadata |
| `UPSTREAM_X_DEVICE_MODEL` | No | Optional upstream device model |
| `UPSTREAM_X_DEVICE_OS` | No | Optional upstream operating system |
| `UPSTREAM_X_VER_OS` | No | Optional upstream OS version |
| `UPSTREAM_X_APP_VERSION` | No | Optional client version |
| `DATABASE_URL` | Yes for panel data | Supabase PostgreSQL URL |
| `ADMIN_USERNAME` | Yes for panel | Login name |
| `ADMIN_PASSWORD` or `ADMIN_PASSWORD_HASH` | Yes for panel | Login password or supported password hash |
| `SESSION_SECRET` | Yes for panel | Long random value used to sign sessions |
| `SYNC_KEY` | Yes for Apps Script | Shared secret sent as `X-Sync-Key` |
| `DRIVE_SYNC_URL` | Yes for instant panel updates | Deployed Apps Script Web App URL ending in `/exec` |
| `DRIVE_API_KEY` | Yes to show Drive subscription links | Google Drive API key, returned only to authenticated administrators |
| `HAPP_PROVIDER_CODE` | Yes for limited links | Happ provider code (8 letters or digits) |
| `HAPP_AUTH_KEY` | Yes for limited links | Happ provider authorization key (32 supported characters); keep it only in Render secrets |
| `HAPP_PROVIDER_ID` | Optional | Eight-character provider ID included in generated profile metadata when valid |
| `mcp_hash` | Optional | 64-character hexadecimal secret that enables the MCP admin endpoint; keep it only in Render secrets |

`ADMIN_PASSWORD_HASH`, when set, takes precedence over `ADMIN_PASSWORD`. Supported encodings are `pbkdf2_sha256$salt$urlsafe_base64_digest` (310,000 PBKDF2-SHA256 rounds) and `scrypt$salt$urlsafe_base64_digest` (`n=16384, r=8, p=1`). Keep the hash string in Render secrets just like a password. Use a random `SESSION_SECRET` of at least 32 characters. If the admin credentials or `SESSION_SECRET` are missing or invalid, panel API access is disabled. If `SYNC_KEY` is missing, Apps Script endpoints are disabled. The relay itself remains available if the database cannot connect.

Use a Supabase connection string from **Project → Connect**. Render may not be able to reach a direct `db.<project>.supabase.co` host over IPv6. In that case choose **Session pooler** in Supabase and put that connection string in `DATABASE_URL`; the service accepts both direct connections and pooler users such as `postgres.<project-ref>`. The connection is made with SSL and individual connection parameters rather than passing the URL to the driver. For a password with spaces or reserved URL characters, percent-encode them (` ` → `%20`, `@` → `%40`, `%` → `%25`). Raw spaces and `@` in the password are parsed too, but percent-encoding is preferred. Never paste the real database password into GitHub, documentation, issues, or logs.

On first successful database connection the service runs `schema.sql` idempotently, seeds settings, and creates the legacy subscriber if it is not already present. The pool is small and lazy; temporary database failures do not stop the relay. The admin page reports a safe connection error and the Session Pooler recommendation.

## Local setup

1. Install Python 3.10+ and run `pip install -r requirements.txt`.
2. Copy `.env.example` to `.env` and fill the values needed for your environment. Do not commit `.env`.
3. Run `uvicorn app:app --host 0.0.0.0 --port 8000`.
4. Open `https://<service>/admin` (or the local URL) and log in with `ADMIN_USERNAME` and the configured password.

## Google Apps Script installation

The source is [`apps_script/Code.gs`](apps_script/Code.gs). Replace the contents of the existing Apps Script project with this file; keep the existing `updateSub` time trigger set to every five minutes as a recovery path. The current script also reports which activation generation it wrote, so the primary confirmation page waits for the full Drive profile before showing the encrypted Happ link.

1. In Apps Script open **Project Settings → Script Properties** and set `RENDER_URL` to the deployed service base address and `SYNC_KEY` to the same secret configured for the service. Do not put either value in `Code.gs`.
2. Save the script, choose `setup` in the function selector, and run it once. It validates the properties and deliberately does not create or delete triggers.
3. Run `updateSub()` once and approve the Google Drive and external request permissions. This initial run updates existing files and creates files for current users.
4. In Apps Script click **Deploy → New deployment → Web app**. Set **Execute as** to your account and **Who has access** to **Anyone**, then deploy and approve access. Copy the Web App URL ending in `/exec`.
5. In Render add `DRIVE_SYNC_URL` with that `/exec` URL and redeploy. `SYNC_KEY` must match the Script Property. The Web App checks this secret on every request; do not share the URL together with the key.
6. Keep the existing `updateSub` trigger. Thereafter user, server, and profile setting changes made in `/admin` call the Web App immediately; no manual Apps Script run is needed. If the trigger already owns the Drive lock, targeted main-user IDs are queued and a fresh cached manifest is processed as soon as the current pass finishes; work left by the Apps Script time budget remains queued for the next trigger.

### Test environment

The `/test` panel uses the same interface and provider feeds as `/admin`, but stores users, servers, settings, and sync state in the separate PostgreSQL schema `secure_x_test`. The schema and its default settings are initialized automatically on the first connection. It does not seed or reuse the legacy production subscription. Test and production sessions use separate cookies.

Create a dedicated Google Drive folder for test subscriptions and set its folder ID as the Apps Script Script Property `TEST_DRIVE_FOLDER_ID`. Do not use the folder that contains production subscriptions. The test panel sends test sync requests to Apps Script, which creates new test profiles only inside that folder; updates and revocations use the test profile's saved file ID. The existing `updateSub` trigger keeps production profiles current and also refreshes test profiles in the separate folder when its ID is configured. If Apps Script is busy during a test update, it queues that test sync for a later trigger.

The test panel and generated subscription are visibly marked **ТЕСТ**. Each generated server key ends with `· ТЕСТ`, and new Drive files start with `ТЕСТ ·`. Test keys still connect to the configured provider servers, so use them to check profile formatting and delivery, not as a separate VPN network.

Test Happ profiles use a near-black custom theme and pin the subscription at the top of the app list. These controls are emitted only for `/test` and require a valid eight-character `TEST_HAPP_PROVIDER_ID`; test profiles never fall back to the production `HAPP_PROVIDER_ID`. For the activation flow, Happ imports the encrypted `/test/sub/...` link on the Render host while Render reads the profile body from the separate test Drive folder. Add the exact Render hostname shown in the test panel's settings to the Happ account that owns `TEST_HAPP_PROVIDER_ID`. A direct Google Drive link has a different source domain and does not use that Render domain binding. Happ documents custom `color-profile` themes for iOS; pinning uses its `subscription-pin` profile parameter. Updated profiles reach Drive on the next Apps Script sync.

Test subscriptions can enable **Активация · ТЕСТ** from the separate **Активация** menu. Each test subscriber gets a unique Render URL. It can be added to Happ as a valid placeholder profile; its information button opens the browser confirmation page. The page detects iOS/iPadOS, Android/Android TV, Windows, macOS, Linux, ChromeOS, Apple Vision, and Apple TV when possible, and allows manual platform selection. After confirmation, Render issues a different encrypted subscription URL for that registered browser slot. Happ's public link-encryption endpoint hides that URL; no Happ Provider code, authorization key, or install counter is used for this test limit. The slot URL checks Render's test database and serves that subscriber's Google Drive profile only after registration. The activation limit is 1–20. A random HttpOnly cookie recognizes the same browser; clearing cookies or using another browser uses another slot. This is browser-based recognition, not a hardware fingerprint, so sharing a slot's encrypted subscription URL can also share its access. IP addresses and hidden browser fingerprints are not stored. Resetting activations issues a new website URL and revokes all old Render slot URLs.

The test server catalog keeps Secure X servers before SAS and tracks provider order independently for each source. When a source adds, removes, or reorders a server, its catalog order updates automatically; **Обновить кэш · ТЕСТ** also forces a rebuild. Old provider entries and their personal overrides are pruned after 60 days absent. Custom names and visibility settings are preserved for retained servers. Edits, cache data, and Drive syncs remain in the test environment, and failed source refreshes preserve the last working cache and profiles.

When a test subscription is created with a Geo-file limit (1–20), it starts with one working server named **Скачать geo-файлы · ТЕСТ** and a Happ routing profile that requests `geoip.dat` and `geosite.dat` from test-only endpoints. After both files are served, the test service triggers an immediate targeted Apps Script sync; the next subscription refresh includes all servers. The configured number caps requests to each Geo-file endpoint and is only an approximate download counter, not a unique-device limit or VPN access restriction.

When updating an already deployed script, use **Deploy → Manage deployments → Edit → New version → Deploy** so the existing `/exec` deployment URL remains the same. Revoking a profile updates the Drive file's media with Drive API v3 using the Apps Script user's OAuth token. Drive API v3 must be enabled in the Cloud project linked to this Apps Script project, and the script owner must authorize Drive access again if Google asks. The same Drive file ID and public URL are kept so Happ can fetch the revocation profile on its next refresh.

The Web App receives targeted updates for an individual subscriber and updates all profiles when global server/settings values change. It fetches the manifest from Render, skips file writes when the contents are identical, and reports Drive IDs and results back to Render. New users get a text file shared as **Anyone with the link — Viewer**; existing files are updated in place. A user you manually delete in the panel is marked `pending_delete`; Apps Script replaces the content of that same Drive file with one nonworking server named **Подписка отключена**, reports success, and Render then removes the user row. The subscription URL therefore remains valid and refreshes to the disabled profile instead of returning 404, which could leave Happ using its last imported servers. If the provider is unavailable, Render still returns pending deletions to Apps Script so they can be revoked while active profiles remain untouched. The five-minute `updateSub()` trigger remains a repair/recovery path.

Apps Script compares the current file text with generated content and skips `setContent` when it is identical. Each active profile gets the same fixed description format: remaining subscription days, a unique six-character ID, and a short Secure X thank-you. The day count is recalculated in each manifest; the existing five-minute trigger delivers changed text to Drive. IDs are unique within each environment's database and are cleared when a subscription expires, is disabled, or is revoked; the previous ID is not kept in an ID history. Main and test each use the same behavior with separate database scopes. Drive is written only when the generated profile text changes. The Apps Script execution keeps a user cursor if it approaches the six-minute runtime limit and resumes on the next trigger.

Happ reads the latest saved Drive file; refreshing it does not itself call Render or Apps Script. The five-minute Apps Script trigger updates a changed remaining-days count in Drive, so Happ receives it on its next subscription refresh.

## Panel and subscription behavior

- **Dashboard:** upstream cache and warning, provider account traffic, subscriber counts, instant Drive delivery status, database status and delivery errors.
- **Subscriptions:** search and filter profiles by SAS inclusion or status; create/edit subscription source selection, enabled state, expiry and profile title; view a generated preview, copy the Drive link, show its QR code, and deactivate profiles. Active profiles show their remaining days and six-character ID in the description. New users include SAS by default; the default can be changed in Settings. The Drive URL is preloaded in the authenticated admin list so the mobile copy action runs directly in the tap gesture; if the browser blocks it, the panel opens a selectable link field. User changes are sent to Drive immediately.
- **Servers:** source badges distinguish Secure X and SAS. Secure X servers are listed before SAS. Search and filter the catalog, select multiple servers, then stage show/hide, rename, and order changes and apply them with one **Готово** action and one Drive sync. Bulk rename supports a prefix, suffix, and find/replace. Per-user rename/hide changes are also staged and saved together for that subscription. When provider membership or order changes, the catalog automatically adopts the new per-source order; **Обновить кэш** and **Обновить источники** force that reset. Custom names and visibility settings remain intact. Entries absent from both feeds for 60 days are deleted with their personal overrides. Failed source refreshes preserve the last working cache and Drive profiles. The refresh result reports counts for each source. If a provider changes a server URI but keeps its name, the existing server identity and global/per-user customizations are retained within that source. Same-connection entries with different provider labels are kept as separate named nodes.
- **Settings:** profile title, support URL, update interval, timezone, new-user traffic visibility and SAS inclusion defaults. Choose whether Drive stores URL lists or native Xray JSON. Changing the format requires a separate confirmation and immediately queues an update of all Drive subscriptions. JSON mode merges the provider and SAS Xray `outbounds` directly, validates every source and the final JSON, preserves per-user SAS and server visibility, and changes an existing `meta.serverDescription` to `SecureX` without adding it when absent. Happ's text-only headers (profile title, traffic info and activation button) are not emitted in JSON mode; inactive or unactivated profiles still receive a non-working placeholder.
- **Device limits:** set a default for new profiles or choose 1–99 devices per profile. Leave the default blank for unlimited profiles. Secure X creates the Happ install counter after the Google Drive file exists, then encrypts the Drive URL as a Happ Limited Link. The panel reports waiting, ready, or error status and lets an administrator retry.
- **Активация · ТЕСТ:** manage each subscriber's unique Render URL, the 1–20 slot limit, registrations, platform/browser metadata, and reset action. Render validates each confirmed slot and serves the current Google Drive profile through a separate encrypted URL. This test flow does not use Happ Provider credentials or Happ install counters.
- Changing a profile's device count creates a new Happ counter after explicit confirmation; previously issued links remain usable by people who already added them. **Rebuild link** encrypts the current Drive URL again with the existing counter. The Happ API can disable counters, but Secure X currently stores only the install code and not Happ's numeric counter ID; disable an older counter in the Happ provider dashboard if needed. For limited profiles the card's primary copy and QR actions use the encrypted Happ link; the separate **Drive без лимита** action remains available for administrators. Keep `HAPP_AUTH_KEY` in Render secrets; it is not included in the Apps Script manifest or application logs.
- `/api/sync/manifest` combines the primary provider subscription and SAS subscription. Every profile can include or omit SAS independently; existing profiles keep SAS enabled. Every SAS node named **LTE — Обход глушилок** is excluded regardless of its number; all other servers are retained. The scheduled Apps Script request refreshes SAS every five minutes; panel server-list refreshes also check both sources. Each source has an independent five-minute cache and keeps its last successful copy during temporary failures. If no SAS snapshot exists, active profiles that include SAS are left untouched; profiles that opted out can still update from Secure X. The service uses only configured `UPSTREAM_*` device headers and fallback User-Agent `Happ`. HTML, device-limit responses, malformed JSON and bodies without supported servers are rejected without replacing the last good subscription. The panel accepts plain or Base64 share-link lists, Xray JSON, sing-box JSON, and Clash YAML. URL mode requires structured proxies to map cleanly to share links and rejects unsupported proxy types with a readable protocol name. JSON mode keeps native Xray outbound objects and applies catalogue visibility only to nodes the admin catalogue can identify. Xray TCP, WebSocket, gRPC and XHTTP VLESS nodes retain TLS/Reality settings, XHTTP `extra` and `finalmask`; provider labels and raw spaces in URI fragments are preserved and safely URL-encoded in generated URL profiles.
- Relay and panel caches are separate. The relay refreshes its combined snapshot every five minutes. Generated profiles keep the primary provider's `subscription-userinfo` values and include SAS only when enabled for that subscriber. The Apps Script compares each generated profile with the current Drive file and skips `setContent` when unchanged.

Generated Google Drive profiles show the provider's `subscription-userinfo` usage by default. The **Основная (legacy)** profile always shows it. For a user profile, the admin can turn on **Скрывать счётчик трафика в Happ**; the setting **Скрывать счётчик по умолчанию** applies only to newly created profiles and can be overridden per user. The shown upload, download, quota and provider expiry are the provider account's shared values, not per-user measurements. A custom expiry set in the panel is also shown in the generated profile. After expiry, the profile remains stored and contains one nonworking placeholder server named **Время подписки закончилось**. Expired profiles are never automatically removed. Deletion in the panel replaces the file contents with one nonworking **Подписка отключена** server and removes the user row after Apps Script confirms the update. Clients must refresh the subscription to receive that replacement; this service cannot remotely erase credentials already imported by a client, and the VPN links connect directly to the provider's servers. Per-user traffic measurement/enforcement and device usage are not available through the shared Drive URL.

The primary panel can enable **Активация** per subscription. It issues a unique activation URL and shows a placeholder profile until a browser slot is confirmed. After confirmation, Render records the slot, requests an immediate Drive update, and shows the encrypted Happ link only after Apps Script confirms it wrote the matching activated profile. Happ then refreshes the subscriber's Google Drive profile directly, so subsequent profile refreshes do not pass through Render. Limits range from 1–20 browser-cookie slots; this recognizes browsers, not physical devices, and a copied subscription URL can be shared. This mode does not use Happ Provider credentials or install counters. It is separate from the existing Happ-managed 1–99 device-limit feature, which remains available for ordinary profiles. If `HAPP_PROVIDER_ID` is set, generated profile metadata includes it on the next normal Drive sync.

The isolated test panel's **Активация · ТЕСТ** uses the same flow in test-only tables and the test Drive folder, independently of primary registrations and files.

The admin UI has separate desktop and mobile pages. `/admin` selects a layout using viewport width and pointer capability; `/admin/desktop` and `/admin/mobile` open either layout directly. Shared CSS and JavaScript are served as local static assets without a build step or third-party CDN.

## Migration without changing the existing link

1. Configure Render environment variables and deploy this version. Keep the current Apps Script running while Render builds; panel and synchronization API routes remain unchanged.
2. Confirm `/health` returns `ok`, then open `/admin` and confirm the database status is connected. If it is unavailable, use the Supabase Session Pooler URL.
3. Confirm the dashboard reports a successful upstream snapshot and a nonzero server count. A failed/empty manifest is not sent to Apps Script as a valid user list, so it cannot overwrite the current Drive file.
4. Replace the old Apps Script source, set the Script Properties, run `setup()` and `updateSub()` once, then deploy it as a Web App and configure its `/exec` URL as `DRIVE_SYNC_URL`. The legacy subscriber continues writing to its existing Drive file; its Drive API URL does not change.
5. Confirm the old Happ link still loads, then create additional users in the panel. Their Drive files and links are created immediately by the Web App.

The project has no dependency on an Apps Script trigger recreation: the existing five-minute trigger name remains `updateSub`.

## MCP for AI agents

Set `mcp_hash` in Render to a private 64-character hexadecimal value. The MCP endpoint is `https://zeva-online.onrender.com/mcp/agent/<mcp_hash>` and uses Streamable HTTP. If the variable is empty, the endpoint is not mounted. The secret in the URL grants administrative access; keep it out of source control, screenshots, and shared logs. Access logs redact this path segment.

The MCP server operates the primary `/admin` environment only. Its tools cover dashboard and integration status, subscription creation/editing and batch changes/revocation, exact lookup by the six-character profile ID (`find_subscription_by_public_id`) followed by the existing subscription management tools, exact profile preview and explicitly requested private links, Render activation slots and limits (including removal of one selected browser slot), global and per-subscription servers, bulk rename/show/hide/order actions, provider refresh/cache rebuild, settings, and immediate Drive sync. Happ-managed 1–99 device limits can be managed only in the admin panel, not through MCP; MCP-created subscriptions do not inherit the panel's optional Happ limit default. Status, settings, and server-list reads use the latest cached snapshot for speed; use the explicit provider refresh tool when fresh source data is needed. Existing admin API validation and Apps Script delivery are reused. Mutating tools require `confirm=true`; bulk profile changes are sent with one targeted Drive sync. The test schema and `/test` panel are not exposed through MCP.

## Tests

Run the isolated test suite with `python -m unittest -v`. Network calls in the new panel tests use local HTTP mocks. They do not access the real provider subscription, Google, or Supabase. No database integration test runs unless one is explicitly added and configured separately.
